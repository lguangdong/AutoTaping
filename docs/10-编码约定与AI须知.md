## 二、文件组织

### 2.1 一个文件一个 public 类型

```
✅ MotionCard.cs  → public interface IMotionCard
✅ Recipe.cs      → public sealed class Recipe
❌ 把 5 个 DTO 塞进 Models.cs
```

**例外**：小型 `record` / `enum` 可以同文件，但不超过 3 个且高度相关。

### 2.2 文件头注释（强制）

```csharp
// 职责：雷赛运控卡的 P/Invoke 实现
// 层：Hardware/Motion
// 依赖：LTDMC.dll（原生）、IMotionCard（Core）
```

### 2.3 目录结构

```
AutoTaping.Core/
├── Abstractions/     # 只放接口和事件参数
├── Models/           # 纯数据类，无行为
├── StateMachine/     # 状态与迁移
├── Flow/             # 流程引擎与步骤
└── Services/         # 有行为的业务服务
```

**禁止**：在 `Models` 里写数据库访问、在 `Abstractions` 里写实现。

## 四、异步与线程（AI 最容易错的地方）

| # | ❌ 错误写法 | ✅ 正确写法 | 后果 |
|---|---|---|---|
| 1 | `async void Foo()` | `async Task FooAsync()` | 异常无法捕获，进程崩溃 |
| 2 | `Thread.Sleep(1000)` | `await Task.Delay(1000, ct)` | 阻塞线程池 |
| 3 | `.Result` / `.Wait()` | `await` | 死锁 |
| 4 | UI 线程 `Task.Run(...).Wait()` | `await Task.Run(...)` | 界面卡死 |
| 5 | 后台线程直接 `_list.Add(...)` | `Dispatcher.Invoke` 或快照 | `InvalidOperationException` |
| 6 | `catch { }` 空捕获 | `catch (Exception ex) { _log.LogError(...); }` | 故障无迹可查 |
| 7 | 忘记传 `CancellationToken` | 所有长任务都要传 | 无法停止 |
| 8 | `Task.Delay` 不带 ct | `Task.Delay(ms, ct)` | 停止时卡住 |

### 唯一允许的 `async void`

事件处理器（如 `Button_Click`），且**必须 try-catch 包裹全部逻辑**：

```csharp
private async void OnStartClick(object sender, RoutedEventArgs e)
{
    try { await _vm.StartAsync(); }
    catch (Exception ex) { _log.LogError(ex, "启动失败"); _notifier.Error(ex.Message); }
}
```

### 运控卡调用必须加锁

```csharp
// DLL 非线程安全，并发调用会导致位置错乱或崩溃
private readonly SemaphoreSlim _lock = new(1, 1);

public void MoveAbsolute(...)
{
    _lock.Wait();
    try { /* P/Invoke */ }
    finally { _lock.Release(); }
}
```

## 五、WPF 专项

| # | ❌ 错误 | ✅ 正确 |
|---|---|---|
| 1 | 后台线程创建的 `BitmapSource` 直接绑 UI | 必须 `.Freeze()` |
| 2 | View 里写 `Background="#FF123456"` | 引用资源 `{StaticResource BgPanel}` |
| 3 | ViewModel 里 `MessageBox` | `IUserNotifier`（便于测试） |
| 4 | 属性 setter 里做 IO / 计算 | 只赋值 + `SetProperty`，重活放命令 |
| 5 | `ObservableCollection` 高频 Add | 批量替换或虚拟化 |
| 6 | 200ms 刷新整个集合 | 更新快照对象，让绑定只刷数值 |
| 7 | 忘记 `Mat` / `Bitmap` 的 `Dispose` | 全部 `using` |
| 8 | 用 `Grid` 堆十层嵌套 | 超过 4 层考虑拆 UserControl |

### ViewModel 模板

```csharp
public sealed partial class ManualViewModel : ObservableObject, IDisposable
{
    private readonly IMotionCard _motion;
    private readonly IUserNotifier _notifier;
    private readonly ILogger<ManualViewModel> _log;

    [ObservableProperty] private double _xPosition;

    public ManualViewModel(IMotionCard motion, IUserNotifier notifier,
                           ILogger<ManualViewModel> log)
    {
        _motion = motion; _notifier = notifier; _log = log;
    }

    [RelayCommand(CanExecute = nameof(CanJog))]
    private async Task JogAsync(string axisName) { /* ... */ }

    private bool CanJog() => _motion.IsConnected && !IsAnyAxisMoving;

    public void Dispose() { /* 取消订阅、停定时器 */ }
}
```

**要求**：所有订阅了事件 / 创建了定时器的 ViewModel 必须实现 `IDisposable` 并在页面卸载时释放。

## 六、异常处理规范

### 6.1 异常类型

| 类型 | 用途 | 谁抛 |
|---|---|---|
| `HardwareException` | 硬件调用失败（带设备名 + 错误码） | Hardware 层 |
| `FlowException` | 流程步骤失败（带步骤名 + 可读原因） | Flow 层 |
| `ValidationException` | 参数校验失败（带字段名 + 范围） | Core |
| `BusinessException` | 业务规则拒绝（如权限不足） | Core |

### 6.2 处理原则

```csharp
// ✅ 正确：分层处理，带上下文
try
{
    await _motion.MoveAndWaitAsync(AxisId.X, pos, speed, 5000, ct);
}
catch (HardwareException ex)
{
    _log.LogError(ex, "X 轴移动失败，目标 {Pos}mm", pos);
    _alarm.Raise("AL104", $"X 轴移动超时，目标 {pos:F2}mm");
    throw new FlowException($"移动失败：{ex.Message}", ex);
}
```

```csharp
// ❌ 错误：吞异常
try { await _motion.MoveAbsolute(...); }
catch { }
```

### 6.3 绝对禁止

- ❌ `catch { }` / `catch (Exception) { }` 空捕获
- ❌ 用 `throw new Exception("...")`，必须用具体异常类型
- ❌ 把异常 `ToString()` 直接显示给操作工（要转成人话）
- ❌ 在 `finally` 里 `throw`

## 七、日志规范

### 7.1 级别使用

| 级别 | 用在哪 | 例子 |
|---|---|---|
| `Debug` | 每步执行、位置数值 | `"执行步骤 5/16 CaptureAndCorrect"` |
| `Information` | 状态迁移、用户操作、产量 | `"状态 Ready -> Running"` |
| `Warning` | 可恢复异常、重试、接近阈值 | `"MARK 匹配分偏低 0.68"` |
| `Error` | 报警、硬件失败 | `"X 轴移动失败"` |
| `Fatal` | 进程无法继续 | `"数据库无法打开"` |

### 7.2 结构化日志（用占位符，不要字符串拼接）

```csharp
// ✅
_log.LogInformation("轴 {Axis} 移动到 {Position:F2}mm，速度 {Speed:F1}mm/s",
                    axis, position, speed);

// ❌
_log.LogInformation("轴 " + axis + " 移动到 " + position + "mm");
```

### 7.3 关键必记日志

| 事件 | 级别 | 必含字段 |
|---|---|---|
| 应用启动/退出 | Information | 版本、硬件模式 |
| 状态迁移 | Information | From、To、触发原因 |
| 用户登录/登出 | Information | 用户名、角色 |
| 参数修改 | Information | 参数名、旧值、新值、用户 |
| 配方切换 | Information | 旧配方、新配方 |
| 每件产出 | Debug | 序号、结果、节拍、纠偏量 |
| 报警触发 | Error/Warning | 代码、内容、来源 |
| 硬件异常 | Error | 设备、操作、错误码 |

**日志文件**：`logs/autotaping-{yyyyMMdd}.log`，按天滚动，保留 90 天。
路径相对可执行文件目录：`src/AutoTaping.App/bin/Debug/net8.0-windows/logs/`。

**调试输出**：`App.ConfigureLogging` 额外挂了 `Serilog.Sinks.Debug`，在 VS 里 F5 调试运行时，
日志会同步出现在「输出 → 调试」（来源选「调试」）。
Console sink 在 WPF（WinExe）下没有控制台，看不到，不要指望输出窗口出现控制台输出。

## 八、配置与魔法数字

```csharp
// ❌ 错误：魔法数字
if (elapsed > 5000) throw new TimeoutException();
Task.Delay(200);

// ✅ 正确：来自配置或常量
if (elapsed > _options.MoveTimeoutMs) throw new TimeoutException();
await Task.Delay(_options.PollIntervalMs, ct);
```

**规则**：
- 硬件参数 → `appsettings.json`
- 工艺参数 → 配方
- 纯算法常量（如轮询间隔 10ms）→ `static readonly` 常量并注释原因
