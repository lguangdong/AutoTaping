# 自动贴胶机上位机（AutoTaping HMI）—— 工程文档集

> **本目录的用途**：这是一套"可直接交付给 AI 编码"的完整技术文档。
> 目标是从零实现一台**自动贴胶机**的 Windows 上位机（设备级 HMI）。
> 编码 AI 必须按文档顺序阅读，并以本文档集的约束为准，不得自行发明功能。

---

## 1. 项目定位

| 项 | 说明 |
|---|---|
| 项目名称 | AutoTaping（自动贴胶机上位机） |
| 软件层级 | L1 设备级上位机（Edge / Machine Control） |
| 运行环境 | Windows 10 / 11，工控机单机部署，**不联网也能完整运行** |
| 使用者 | 操作工（操作员）、技术员、售后工程师 |
| 核心职责 | 人机交互、视觉定位、运动调度、IO 时序、配方管理、报警、产量统计、本地追溯 |
| **不负责** | 实时伺服闭环、插补曲线规划。这些由雷赛运控卡内部完成 |

## 2. 已知硬件清单

| 硬件 | 状态 | 对软件的影响 |
|---|---|---|
| 海康**黑白**工业相机 | ✅ 已有 | 走 `MvCameraControl.Net`，像素格式按 `Mono8` 处理 |
| 雷赛运动控制卡 | ✅ 已有 | 走 `LTDMC.dll` P/Invoke，**需按实际型号核对函数名** |
| 工控机 | ⬜ 待确认 | 影响 .NET 版本与屏幕分辨率 |
| 触摸屏 | ⬜ 待确认 | 影响控件尺寸（触摸按 60×60 起） |
| 三色灯 + 蜂鸣器 | ⬜ 待确认 | 通过运控卡 DO 输出 |
| 贴胶头（气缸/真空/吸嘴） | ⬜ 待确认 | 通过运控卡 DO/DI 控制 |
| 伺服/步进电机 | ⬜ 待确认 | 轴数量决定 UI 手动页布局 |

### ⚠️ 两个必须确认的硬件参数

1. **雷赛运控卡型号**（如 DMC2410 / DMC2410C / DMC5800 / SMC6490）
   - 不同型号 `LTDMC.dll` 的函数签名和轴数不同
   - 本文档 `02-硬件对接-雷赛运控卡.md` 以 **DMC2410 系列**为参考
   - 若型号不同，**只改 `LeadshineMotionCard.cs` 一个文件**，接口不变

2. **海康相机型号与分辨率**（如 MV-CA013-20GM / MV-CS050-10GM）
   - 影响：最大分辨率、帧率、是否支持硬件触发
   - 本文档 `03-硬件对接-海康相机.md` 以 **Mono8 / 软触发**为默认

## 3. 技术栈（锁定，不允许替换）

| 类别 | 选型 | 版本要求 | 理由 |
|---|---|---|---|
| 运行时 | .NET 8 (Windows) | ≥ 8.0 | LTS，性能与部署都成熟 |
| UI | WPF | 内置 | 工控行业主流，设计器能力强 |
| MVVM | CommunityToolkit.Mvvm | 8.x | 轻量，Source Generator，不引入重框架 |
| 依赖注入 | Microsoft.Extensions.DependencyInjection | 8.x | 官方，够用 |
| 日志 | Serilog + Serilog.Sinks.File | 3.x | 结构化日志，按天滚动 |
| 配置 | Microsoft.Extensions.Configuration.Json | 8.x | `appsettings.json` |
| 数据库 | SQLite + Dapper | Dapper 2.x | 轻量，SQL 可控，便于 AI 生成 |
| 视觉 | OpenCvSharp4 + OpenCvSharp4.runtime.win | 4.9+ | 标定、模板匹配、图像处理 |
| 相机 SDK | MvCameraControl.Net（海康官方） | 随 MVS 安装 | 必须用官方 SDK |
| 运控 SDK | LTDMC.dll（雷赛官方，P/Invoke） | 随卡驱动 | 必须用官方 DLL |
| 测试 | xUnit | 2.x | 纯逻辑单元测试 |

### 明确禁止

- ❌ 禁止引入 Prism / Caliburn.Micro / MahApps / MaterialDesign 等重型框架或 UI 库
- ❌ 禁止引入 NModbus / 任何 Modbus 库（本项目不走 Modbus，直接调运控卡 DLL）
- ❌ 禁止使用 Entity Framework（表结构简单，Dapper 足够，避免迁移复杂度）
- ❌ 禁止使用 `async void`（事件处理器除外）
- ❌ 禁止在业务代码里出现 `Thread.Sleep`（除运控轮询的受控延时，且必须用 `IClock` 抽象）

## 5. 给编码 AI 的使用顺序

```
第 1 步：读 README.md + 00-项目总览.md + 01-架构设计.md   → 建立全局认知
第 2 步：读 10-编码约定与AI须知.md                       → 明确红线
第 3 步：读 11-开发任务分解.md                           → 选当前阶段
第 4 步：按阶段需要，读对应技术文档
第 5 步：编码 → 用该阶段的"验收标准"自检
```

### AI 生成代码时的强制要求

1. **每个文件开头写 3 行注释**：文件职责、所属层、依赖项
2. **接口先于实现**：先定义接口，再写实现，再写模拟实现
3. **每个 public 类必须有 XML 文档注释**（`<summary>`）
4. **不允许"顺手优化"未在任务中要求的模块**
5. **不允许改变已定义的接口签名**（如需变更，先说明理由并征求确认）
6. **每个阶段结束必须能编译通过且可运行**

## 6. 全局硬约束

| 约束 | 说明 |
|---|---|
| **单机运行** | 断网状态下所有核心功能可用（MES 已排除，本约束天然满足） |
| **不崩** | 任何硬件异常（相机掉线/运控卡失效）只能报警，不能让 UI 崩溃 |
| **可降级** | 相机未连接时，允许"手动模式"完整可用 |
| **可模拟** | 无硬件环境下必须能启动完整 UI（用 Virtual 实现） |
| **参数热生效** | 改参数不重启，最多影响下一个节拍 |
| **数据不丢** | 产量、报警、日志必须落本地 SQLite，断电后不丢已提交数据 |
| **权限三级** | 操作员 / 技术员 / 工程师，界面元素按权限显隐 |
