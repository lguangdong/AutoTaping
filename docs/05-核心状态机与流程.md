## 1. 两个正交概念：模式 与 状态

很多新手把"手动/自动"和"运行/停止"混成一个枚举，导致状态爆炸。本项目严格分开：

### 1.1 操作模式（OperationMode）

```csharp
public enum OperationMode
{
    Auto,     // 自动模式：可启动自动流程
    Manual    // 手动模式：只能点动、单轴操作
}
```

**规则**：运行中（`Running`）禁止切换模式。

### 1.2 设备状态（DeviceState）

```csharp
public enum DeviceState
{
    Initializing,   // 启动自检中
    NotReady,       // 未就绪（未回零 / 相机未连接 / 气压低）
    Ready,          // 就绪，等待启动
    Running,        // 自动流程执行中
    Paused,         // 暂停（可在当前步骤结束后恢复）
    Alarming,       // 报警中（需确认 + 复位）
    EStopped,       // 急停中（需释放 + 复位 + 重新回零）
    Exiting         // 正在退出
}
```

## 2. 状态迁移表（唯一权威，代码必须完全照此实现）

| From | To | 触发 | 守卫条件（全部满足才允许） |
|---|---|---|---|
| Initializing | Ready | 自检完成 | 4 轴已回零 && 相机就绪 && 气压正常 && 无未确认严重报警 |
| Initializing | NotReady | 自检完成 | 上述任一不满足 |
| Initializing | Alarming | 自检发现严重故障 | — |
| NotReady | Ready | 用户点"回零"且成功 | 安全门闭合 && 运控卡连接 |
| NotReady | Alarming | 回零失败 | — |
| Ready | Running | 点"启动" | 模式=Auto && 有激活配方 && 安全门闭合 && 相机就绪 && 气压正常 |
| Running | Paused | 点"暂停" | — |
| Paused | Running | 点"继续" | 无未确认严重报警 && 安全门闭合 |
| Running | Ready | 点"停止" | **执行完当前步骤后**才迁移（非立即） |
| Paused | Ready | 点"停止" | — |
| Running | Alarming | 任一步骤抛 `FlowException` | — |
| Paused | Alarming | 恢复时检查失败 | — |
| Alarming | Ready | 点"复位" | 报警已确认 && 故障源已排除 && EVar 无残留 |
| Ready | NotReady | 配方被删除 / 相机断开 | — |
| 任意（除 Exiting） | EStopped | 急停信号触发（X06=0） | — |
| EStopped | NotReady | 点"复位" | 急停已释放 && `ResetAxis` 全部成功 |
| Ready | Ready | 切换 Auto/Manual | 无轴在运动中 |
| Running/Paused | 任意切换 | — | **禁止** |

## 3. 状态机实现骨架

```csharp
namespace AutoTaping.Core.StateMachine;

public sealed class DeviceStateMachine
{
    private readonly object _sync = new();
    private readonly Dictionary<(DeviceState From, DeviceState To), Func<bool>> _guards = new();
    private readonly ILogger<DeviceStateMachine> _log;

    public DeviceState State { get; private set; } = DeviceState.Initializing;
    public OperationMode Mode { get; private set; } = OperationMode.Auto;

    public event EventHandler<StateChangedEventArgs>? StateChanged;

    public bool TryTransition(DeviceState target)
    {
        lock (_sync)
        {
            if (!_guards.TryGetValue((State, target), out var guard) || !guard())
                return false;

            var old = State;
            State = target;
            _log.LogInformation("状态 {Old} -> {New}", old, target);
            StateChanged?.Invoke(this, new StateChangedEventArgs(old, target));
            return true;
        }
    }

    public bool TrySwitchMode(OperationMode mode)
    {
        lock (_sync)
        {
            if (State is DeviceState.Running or DeviceState.Paused) return false;
            Mode = mode;
            return true;
        }
    }
}
```

### 必须有的单元测试

```
✓ Ready → Running 需要配方（无配方时拒绝）
✓ Running 时切 Manual 被拒绝
✓ EStopped 未释放急停时不能复位
✓ Alarming 未确认报警时不能复位
✓ 所有非法迁移返回 false 且不改变状态
```

## 4. 自动流程（步骤列表）

### 4.1 步骤抽象

```csharp
public abstract class FlowStep
{
    public abstract string Name { get; }
    public virtual int TimeoutMs => 10_000;
    public int RetryCount { get; init; } = 0;

    public abstract Task ExecuteAsync(FlowContext ctx, CancellationToken ct);
}

public sealed class FlowContext
{
    public Recipe Recipe { get; init; } = null!;
    public CalibrationResult Calibration { get; init; } = null!;
    public CorrectionResult? LastCorrection { get; set; }
    public int SequenceNo { get; set; }
    public Stopwatch StepWatch { get; } = new();
}
```

### 4.2 标准步骤序列（产线 + 点贴，严格按此顺序）

| # | 步骤名 | 超时 | 重试 | 失败处理 |
|---|---|---|---|---|
| 1 | `CheckPreconditions` 前置检查 | 1s | 0 | 报警，转 Alarming |
| 2 | `WaitCarrier` 等待载具到位并停线 | 30s | 0 | 超时 → 暂停（AL403，可能只是没料） |
| 3 | `SettleDelay` 停稳延时 | 300ms | 0 | — |
| 4 | `MoveToPhotoPos` 移到拍照位 | 5s | 0 | 报警 |
| 5 | `CaptureAndCorrect` 拍照 + 识别 + 纠偏 | 5s | **2** | 拍照超时重试；识别/纠偏失败 → 报警 `AL201/AL202/AL203` |
| 6 | `MoveToPickPos` 移到料盘取料位 | 5s | 0 | 报警 |
| 7 | `PickTape` Z 下降吸料 + 抬起 | 3s | 0 | 真空吸不住 → `AL301`；料盘缺料 → `AL303` |
| 8 | `MoveToTapePos` 移到贴附位（含 ΔX/ΔY/Δθ） | 5s | 0 | 报警 |
| 9 | `PressAndHold` Z 下降 + 压合 + 保压 | 5s | 0 | 压合未到位 → `AL304` |
| 10 | `ReleaseTape` 吹气断真空 + Z 抬起 | 2s | 0 | 报警 |
| 11 | `RecordOutput` 计数 + 落库 | 1s | 1 | 记录失败不影响生产，但要日志 |
| 12 | `ConveyOut` 传送带放行（**只开带不定时关**，停线由下一拍 `WaitCarrier` 到位后完成） | 5s | 0 | 堵料 → `AL404` |
| 13 | 回到步骤 2 | — | — | — |

> **`MoveToPhotoPos` 为什么必须在拍照之前**：相机是本机 **Eye-in-Hand**（装在贴附头上，随头一起动），
> 拍到的永远是「头当前所在位置的正下方」。若流程直接拍照，首拍时头在回零位、第二拍起头停在上一拍的贴附位，
> MARK 会落到视野外并报 `AL202`。因此拍照前必须把头送到 `PhotoPosX/Y`（`PhotoPos = TapeBase − CameraOffset`）。

> **传送带是连续输送的**：`ConveyOut` 只开带、不做定时关门，停线统一由下一拍 `WaitCarrier` 在 X00 到位后执行，
> 所以「放行 → 等下一件」之间没有空转停顿，节拍时间也不再计入放行等待。
> 代价是**非正常退出必须自己关带**：暂停 / 停止 / 急停 / 流程异常暂停四处都要 `WriteDo(ConveyorRun, false)`，
> 否则带子会继续把载具带走。`RecordOutput` 排在放行之前，节拍口径为「上料到贴完」。

> **与旧版（15 步）的差异**：删掉 `MoveToTapeStart` / `TapePath` / `MoveZToTapeHeight` / `MoveZSafe` / `MoveToUnloadPos` / `VacuumOn` / `VacuumOffAndBlow`，
> 合并为 4 个新步骤：`MoveToPickPos`、`PickTape`、`PressAndHold`、`ReleaseTape`。
> 原因是本机改为**点贴**（无贴附路径）且**工件不动**（无下料位移动，由传送带完成）。

### 4.3 执行器（支持单步与断点续跑）

```csharp
public sealed class AutoFlowEngine
{
    private readonly IReadOnlyList<FlowStep> _steps;
    private int _currentIndex;

    public async Task RunAsync(FlowContext ctx, CancellationToken ct)
    {
        _currentIndex = 0;
        while (_currentIndex < _steps.Count)
        {
            ct.ThrowIfCancellationRequested();
            if (_isPaused) { await WaitResumeAsync(ct); }

            var step = _steps[_currentIndex];
            _log.LogDebug("执行步骤 {Index}/{Total} {Name}",
                _currentIndex + 1, _steps.Count, step.Name);

            await ExecuteWithRetryAsync(step, ctx, ct);
            _currentIndex++;

            if (_singleStepMode) { _currentIndex = 0; return; }  // 单步走一步就停
        }
    }

    private async Task ExecuteWithRetryAsync(FlowStep step, FlowContext ctx, CancellationToken ct)
    {
        for (int attempt = 0; attempt <= step.RetryCount; attempt++)
        {
            using var cts = CancellationTokenSource.CreateLinkedTokenSource(ct);
            cts.CancelAfter(step.TimeoutMs);
            try
            {
                await step.ExecuteAsync(ctx, cts.Token);
                return;
            }
            catch (OperationCanceledException) when (!ct.IsCancellationRequested)
            {
                _log.LogWarning("步骤 {Step} 超时（第 {N} 次）", step.Name, attempt + 1);
            }
            catch (FlowException ex)
            {
                _log.LogWarning(ex, "步骤 {Step} 失败（第 {N} 次）", step.Name, attempt + 1);
            }
        }
        throw new FlowException($"步骤 [{step.Name}] 执行失败");
    }
}
```

**单步模式说明**：`_singleStepMode = true` 时，每次点"启动"只走一个步骤，用于现场调试。
单步模式**必须仅在技术员以上权限可用**，且界面显著提示「单步模式」。

## 5. 异常与恢复策略（必须实现）

| 异常场景 | 处理动作 | 报警码 | 恢复方式 |
|---|---|---|---|
| 拍照失败（超时） | 重试 2 次 → 停止流程 | `AL201` | 检查相机后复位 |
| MARK 识别失败 | 不重试，立即停止 | `AL202` | 检查模板/光照 |
| 纠偏量超阈值 | 不重试，立即停止 | `AL203` | 检查工件放置 |
| 取料真空吸不住（X03=0 超时） | 停止 | `AL301` | 检查气路/真空泵/吸嘴堵塞 |
| 料盘缺料（X02=0 或 X04=0） | 暂停 | `AL303` | 换料盘后继续 |
| 载具未到位（X00=0 超时 30s） | 暂停 | `AL403` | 补料后续跑 |
| 出料侧堵料（X01=1 超时） | 暂停 | `AL404` | 清料后继续 |
| 轴运动超时 | **急停该轴** → 停止 | `AL104` | 手动移开，复位 |
| 轴撞限位 | 停止 | `AL101` | 反向点动退出 |
| 安全门打开（运行中） | **立即暂停**（不是停止） | `AL401` | 关门后点继续 |
| 气压低 | 暂停 + 报警 | `AL402` | 恢复气压后继续 |
| 相机掉线 | 暂停 + 报警 | `AL201` | 恢复后继续（需人工确认） |
| 运控卡掉线 | **立即急停** + 报警 | `AL105` | 修复硬件后重新初始化 |
| 磁盘空间不足 | 报警，继续生产 | `AL501` | 清理后自动恢复 |
| 数据库写失败 | 报警，内存缓冲 | `AL502` | 恢复后补写 |

### 5.1 关键区分：「暂停」vs「停止」

```
暂停（Paused）：保留当前进度，故障排除后点"继续"从当前步骤恢复
停止（Ready）：清空进度，下次从头开始
```

- **安全门打开** → 暂停（人可以关门后继续）
- **MARK 识别失败** → 停止（这件的状态已不可信，必须重来）

### 5.2 急停的强制要求

```csharp
private void OnEmergencyStop()
{
    // 顺序不能变
    _motion.EmergencyStopAll();       // 1. 立刻停轴
    _io.ClearAllForcedOutput();       // 2. 清除强制输出
    _io.WriteDo("Y07", false);        // 3. 停传送带（防止载具继续流动）
    _io.WriteDo("Y00", false);        // 4. 关真空（防坠落/防吸住）
    _io.WriteDo("Y01", false);        // 5. 关吹气
    _io.WriteDo("Y02", false);        // 6. 压合气缸抬起
    _io.WriteDo("Y03", false);        // 7. 绿灯灭
    _io.WriteDo("Y05", true);         // 8. 红灯亮
    _stateMachine.TryTransition(DeviceState.EStopped);
    _alarm.Raise("AL100");
}
```

**急停后所有运动指令必须被拒绝**，直到 `ResetAxis` 成功 + 状态回到 `NotReady`（需要重新回零）。

## 6. 互锁清单（Interlock，真实设备的核心）

以下条件**任一不满足**时的行为，必须严格实现：

| # | 条件 | 不满足时 |
|---|---|---|
| 1 | 4 轴已回零 | 禁止自动运行，提示"请先回零" |
| 2 | 安全门闭合（X05=1） | 运行中→暂停；未运行→禁止启动 |
| 3 | 气压正常（X07=1） | 禁止启动，报警 `AL402` |
| 4 | 相机就绪 | 禁止自动运行 |
| 5 | 运控卡连接 | 禁止一切运动（含手动） |
| 6 | 有激活配方 | 禁止启动 |
| 7 | 急停未触发（X06=1） | 禁止一切动作 |
| 8 | Z 轴在安全高度 | 禁止 X/Y 大范围移动（防撞） |
| 9 | 手动模式无轴在动 | 禁止切回自动 |
| 10 | 有未确认的严重报警 | 禁止启动 |
| 11 | 载具到位（X00=1） | 不允许开始拍照/贴附，停在步骤 2 等待 |
| 12 | 料盘有余料（X02=1） | 禁止取料，报警 `AL303` 并暂停 |

### 6.1 实现方式

```csharp
public sealed class InterlockChecker
{
    public IReadOnlyList<string> CheckForStart(DeviceSnapshot snap, Recipe? recipe)
    {
        var errors = new List<string>();
        if (!snap.AllAxesHomed) errors.Add("4 轴未全部回零");
        if (!snap.Di("X05")) errors.Add("安全门未闭合");
        if (!snap.Di("X07")) errors.Add("气压不足");
        if (!snap.CameraReady) errors.Add("相机未就绪");
        if (!snap.MotionConnected) errors.Add("运控卡未连接");
        if (recipe is null) errors.Add("未选择配方");
        if (!snap.Di("X06")) errors.Add("急停被按下");
        if (snap.HasUnackedCriticalAlarm) errors.Add("存在未确认的严重报警");
        return errors;
    }
}
```

UI 上点"启动"时：`if (errors.Count > 0) { 弹窗列出所有原因; return; }` —— **一次列全，不要让用户一个个试**。

## 7. 节拍与停机统计

### 7.1 节拍定义

```
CycleTime = 从 WaitMaterial 检测到有料，到 RecordOutput 完成
```

**不含**：件与件之间的等待间隙（那属于"待料时间"）。

### 7.2 停机原因分类（必须由流程自动记录）

| 代码 | 原因 | 触发点 |
|---|---|---|
| `WAIT_MATERIAL` | 待料 | `WaitMaterial` 超时 |
| `FAULT` | 故障停机 | 任何报警导致的停止 |
| `MANUAL_PAUSE` | 人工暂停 | 用户点暂停 |
| `CHANGE_RECIPE` | 换型 | 切换配方 |
| `POWER_OFF` | 断电（重启后补记） | 启动时检测上次非正常关闭 |

### 7.3 UPH 计算

```csharp
// 用实际运行时间，不是总时间
double runMinutes = TotalRunSeconds / 60.0;
double uph = runMinutes > 0 ? OkCount / (runMinutes / 60.0) : 0;
```

## 8. 本文件的约束

1. 状态迁移必须走 `TryTransition`，不得直接赋值 `State`
2. 每个 `FlowStep` 必须有超时，不得无限等待
3. 急停处理顺序不得调整
4. 所有互锁必须在**启动前**和**每步执行前**各检查一次
5. 暂停恢复时必须重新检查互锁，不得直接继续
6. 单步模式必须限权限且界面显著提示
