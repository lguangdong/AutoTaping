### 关键设计决策
1. **真实 vs Virtual 选择 + 降级**：不引入 wrapper/selector，直接在 DI 注册工厂内「构造真实→Initialize 探测→失败
   Dispose 并返回 Virtual」，降级结果用单例 `HardwareStartupReport` 传给 InitializeHardware 报 AL105/AL201。
   靠解析顺序保证正确：InitializeHardware 先解析 IMotionCard（置 MotionDegraded），DeviceMonitor 才解析 IIoService
   （据此判断是否 IO 也降级）。
2. **DLL 锁共享**：LeadshineMotionCard 与 MotionCardIoService 用同一个 `SemaphoreSlim`（RegisterHardware 里 new 一次
   闭包捕获），因两者都打同一 LTDMC.dll。
3. **相机 SDK 用条件编译**：MvCameraControl.Net 是海康私有 SDK、不在 NuGet、本机无；用 `#if HAS_MVS` + csproj
   `Exists('libs/MvCameraControl.Net.dll')` 自动切，缺 SDK 也能编译运行（占位降级）。这是唯一让「可编译+可运行」
   与「真实代码已写好」兼顾的方案。

### 关键设计决策 / 踩坑
1. **备份不能用文件复制**：软件运行时连接池句柄一直占着 `.db`（测试实测报 "being used by another process"）。
   改用 `SqliteConnection.BackupDatabase(destination)` 导出到临时库再打包；**临时库连接串必须 `Pooling=false`**，
   否则池化句柄导致 `CreateEntryFromFile` 又读不到该文件。备份期间不影响生产。
2. 自检恢复：`_diskAlarmActive` 是内存标记，重启后丢失 → 条件正常时也调用 `Recover`（AlarmService 对无生效报警是安全无操作），
   否则上次会话遗留的 AL501 永远挂在「当前报警」。
3. 维护/备份/自检全部在 `Data` 或 `Core`，`App` 只依赖接口；`SystemViewModel` 用 `await Task.Run(...)`（默认回 UI 线程），未引入额外 dispatcher。
4. `IBackupService`/`IMaintenanceService`/`ISelfCheckService` 均实现 `IDisposable`，由 `ServiceProvider.Dispose()` 在退出时释放后台循环。
