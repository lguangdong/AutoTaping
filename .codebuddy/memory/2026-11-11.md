## 概念讲解：Jog / 点动（用户问「这里的 jogging 一般用于什么运动」）
- Jog = **点动**（运控术语，与慢跑无关）：速度模式连续运动，只给方向+速度，指令发出后一直走，
  唯一的"刹车"是外部 Stop —— 所以 UI 必须做成"按住才动、松开立即停"。
- 运控三类运动对照：`MoveAbsolute/MoveRelative`（点位，给目标位置，卡自己规划加减速）/
  `JogStart`（连续，给方向速度）/ `Home`（找原点）。项目 `IMotionCard` 正好这三组。
- 典型用途：调试对位、回零前脱困（轴压在限位开关上先反向点开）、维修清料、标定前粗定位到 MARK 附近、
  验证方向与软限位接反、手动上料/换型。
- 项目实现链：`ManualPage.xaml`（`behaviors:PressHoldBehavior.PressCommand/ReleaseCommand`）
  → `AxisControlViewModel.StartJog/StopJog/StopMotionOnLeave`（138~262 行）
  → `IMotionCard.JogStart` → `LeadshineMotionCard.JogStart` 的 `dmc_vmove`（294~315 行）。
- 安全设计：`StopJog` 故意不设 CanExecute（急停时也必须能停，否则松手轴还在动）；
  离开手动页 `StopMotionOnLeave` 强制停；速度范围 1~100mm/s 默认 20（appsettings `Manual:JogSpeedMmPerSec`）；
  虚拟卡走到软限位自动置 `_jogging = false`（模拟撞限位）。
- 工程约束：**自动流程绝不用 Jog**（停在哪不确定、不可重复），一律 MoveAbsolute。
- 项目只实现了 Jog，没实现 Inch（寸动：每按一次走固定小距离，如 0.01mm）。

## 设备构型与拍照位澄清（用户问「步骤三拍照位放的是什么/设备长什么样/轴怎么布置」）
- 结论：拍照位拍的是**工件（被贴胶目标）上的两个 MARK**，不是胶带。依据 `docs/04` 开篇「相机固定（Eye-to-Hand），工件随平台移动」。
- 机械构型：**X/Y 带平台**（台面上放工件治具）+ **Z/R 带贴胶头**（真空吸嘴）。贴胶头**没有 X/Y 自由度**，
  "头相对工件"的平面运动全靠平台带工件走；相机与贴胶头都固定在机架上、沿 X 排列，Y 都在 200。
- 位置参数是**平台坐标**而非机械槽位：拍照位(150,200)=平台走到此处工件 MARK 落进相机视野；
  贴附基准(220,200)=平台走到此处工件的贴附基准正对吸嘴；两者差 70mm ≈ 相机光轴与吸嘴中心的机械间距（示教得来，属推断）；
  下料位(350,200)、旋转中心(220,200)（与贴附基准同点）。默认工艺值：安全高度 50、贴附高度 2、移动 100mm/s、贴附 80mm/s、保压 500ms。
- 物料：工件随平台依次过上料位→拍照位→贴附位→下料位四站；胶带吸在吸嘴端部（Y00 开、X03 确认、Y01 破真空）；
  相机与贴胶头不动。
- **文档/代码空白**：没有「吸取胶带」步骤，也没有供料机构 —— 步骤 7（Z 降到贴附高度）之后步骤 8 直接开真空，
  意味着模型默认胶带已在吸嘴下方（人工预贴或上游料带机构）。真实设备需补一个供料工位与取胶带步骤。
- 贴附物理过程：Z 下压 + 吸住胶带后，步骤 9/10 是**平台带工件走**（`CorrectedBaseX + point.X`），胶带被一路压贴在工件上；
  R 轴只在步骤 6 调整 θ，不参与路径。

## 修正："下一件开始不流畅" + 皮带停走不同步（用户反馈）
- **跳变根因**：第 10 步 `to.hy = 200`，而第 1 步 `from.hy = PHOTO_Y(156)` → 循环回到第 1 步的瞬间，头 Y 从 200 **瞬跳** 156。
  修法：第 10 步就承担"头退到拍照位"（200→156），第 1 步保持 156，边界连续。顺带缩短第 1 步 1500→900、第 9 步 1400→1100。
- **皮带不同步根因**：原来 `if (playing && st.belt) beltPhase += dt*0.0009` 是**按时间累加**，和载具的 ease 缓动位移毫无关系；
  而且 `belt = (n===1 && t<0.82) || n===9` 导致第 1 步皮带空转（载具却不动）。
  修法：改为**位移驱动** `beltTex.offset.x = -(beltTravel + flow) * 9 / 760`，
  `beltTravel` 在 `advanceLine()` 里 += GAP，`flow` 是第 9 步的实时位移 → 皮带与载具严格同速同停；`belt` 简化为 `n===9`。
- **通用经验**：动画里"看起来应该一起动"的东西（皮带 + 载具、头 + 相机），**必须由同一个位移/状态变量驱动**，
  各自计时必然不同步；循环动画的每条边界都要检查 from/to 是否首尾相接。

- **根因**：第 9 步用 `flow = st.cx - 200` 做显示位移，但 `c.x` 要等到下一轮开始（idx 回 0）才 `+= GAP`。
  结果第 10 步 `flow` 归零 → 载具**瞬间回跳**到旧位置，然后 idx=0 再跳一次。两段跳变 = 不流畅。
- **改法**：在第 9 步结束的那一帧（`prev === 8`）立刻 `advanceLine() + pickActive()`，把位移固化进 `c.x`，
  下一帧 `flow=0` 时位置连续。
- 配套修正：① 偏差叠加只在第 6~8 步（9/10 不叠加，避免 active 切换时头位置跳）；
  ② `visible` 用 `c.x + flow` 判断；③ 出线重置阈值 660 / 可见上限 650，保证重置发生在视野外；
  ④ 料盘取料后中间那片隐藏、下一轮补上。
- **教训**：动画里"位移"只能有一个真值来源。同时存在 `flow`（临时偏移）和 `c.x`（持久位置）时，
  必须在同一帧完成"临时量固化"，否则必然回跳。

- **时序 bug**：第 8 步原来 Z 一直在升，胶带在 t=0.3 才脱开，视觉像"吸嘴抬起一段后胶带突然掉落"。
  改为 `hzCurve:'release'` —— 前 35% 保持在贴附高度吹气（胶带落下），后 65% 才抬 Z。
- **多件排队**：改为 4 个载具（`makeCarrier()` 工厂，各自独立材质/偏差/done），间距 `GAP=170`。
  第 9 步放行时整线前移一个间距：`flow = st.cx - 200` 叠加到每个载具；出线件（x>640）回到队尾 `minX` 并重新随机偏差。
  每轮开始 `advanceLine()` + `active = pickActive()`（取最接近 x=200 的那件）。
- **注意**：`STEPS` 的 `cx` 只在第 9 步有意义（200→370），其他步骤恒为 200，载具位置统一由 `carriers[i].x + flow` 决定。

- 相机改为**垂直向下**（去掉倾斜），装在头局部 (0, 58, -44)，视野锥垂直同轴、半径 46。
- **关键做法**：相机与吸嘴在设备 Y 方向偏 44mm，所以**拍照位不是贴附位** ——
  拍照时头站到 `PHOTO_Y = 156`（156+44=200，相机光轴正落工位中心），贴附时头再到 200。
  这是 Eye-in-Hand 的标准处理：偏置靠"站位"补，不靠倾斜相机。
- 来料偏差模拟：工件包进 `pieceGroup`，每件随机 **±4mm / ±1.5°**；第 6 步起把 `piece.dx/dy/dr` 叠加到头目标，
  面板新增"来料 ΔX/ΔY、Δθ"两格；循环回绕时 `randomizePiece()`。
- 真实设备对应：视野半径必须 > 偏差上限（这里 46mm > 4mm，余量充足）；偏置量必须由手眼标定得到，不能靠猜。

- 结论成立：点贴简单得多，而且**更符合 docs/00 第 5 行原始描述**"把定长胶带精确贴附到工件指定位置"——
  TapePath/滚贴是后来为"走路径"引入的，属于自己给自己加难度。
- 机构：删掉压轮 / 胶带卷 / 剥离刀 / 收膜轮 / 张力控制；改为**真空吸嘴 + 预裁胶带料盘**（料盘在设备 Y=80，头 Y 活动 80~200）。
- 流程 10 步，`hz` 改为**绝对世界高度**（安全 66 / 贴附 18 / 取料 12）：
  WaitCarrier → SettleDelay → CaptureAndCorrect → MoveToPickPos → PickTape（`hzCurve:'pick'`，下去吸住再上来）→
  MoveToTapePos（含纠偏）→ PressAndHold → Release（吹气断真空 + 抬起）→ ConveyOut → RecordOutput。
- 点贴省掉：路径插补、Z 随动、R 跟随切线、胶带转移/张力、剥离刀与收膜轮；只剩"取-移-压-吹"四个动作。
- 代价：只能贴**定长片**，贴不了连续长条；需要预裁料盘（换料比换卷频繁）。

- 根因：相机为了避开压轮/头体，装在头局部 X=-42（侧面），光轴因此偏出工件中心 42mm。
- 改法：相机移到**头局部 X=0、Z=-44（前侧）**，与头中心线对齐；视野锥用 `rotation.x=-0.48`（约 -27.5°）**斜指压轮落点**，
  锥尖在镜头、锥底在 (0,-50.6,0) 即工件上方，视觉上工件落在锥中心。
- **物理事实（要讲清楚）**：Eye-in-Hand 的相机因执行器遮挡，光轴不可能与执行器完全同轴，工业上就是"偏置安装 + 手眼标定补偿"，
  工件只要在视野内即可，不要求居中。示意图里把锥斜过来只是为了看起来合理。

- 根因：相机原来**固定装在贴附工位正上方** (200,200)，而贴胶头贴附时也要到 (200,200)，
  头的 Z 伸缩杆（世界 y 152~374）必然穿过相机机身/镜头（252~300）。这是"Eye-to-Hand 固定相机 + 单工位拍照贴附"的**构型矛盾**，不是摆放误差。
- 改法：改为 **Eye-in-Hand** —— 相机（机身/镜头/视野锥）改成 `head` 的子物体，装在头体侧面 (-42)。
  顺带把头待机位从 Y=330 改为 Y=200（不再需要"退让让视野"），第 8 步改为"Z 抬起 + 回中"。
  Z<20 时隐藏视野锥（否则锥体插进工件）。footer 补充"代价是要做手眼标定"。
- 教训：**同一工位既拍照又贴附时，相机必须跟头走（Eye-in-Hand）；固定相机（Eye-to-Hand）就必然要两个位置**。
  这个结论也应写进 docs/04，否则按文档实现会撞。

- 最终按用户要求**只保留一件载具**：`bgCarriers`（两个 clone 的静态背景载具）已整段删除，
  `applyState` 里对应的跟随循环也删掉，全文再无 bgCarriers 引用。以后要"一个隔一个"再按需加回。
- 原因：背景载具是**静止的 clone**，固定钉在 X=-150/470，主件动、它们不动，看着像穿帮道具。
- 改法：位置改为 `主件 cx ± 165` 等间距跟随（停线时随之停住，符合物理），超出 X∈(-270,690) 自动 `visible=false`；
  另外 clone 后必须 `traverse` 逐个 `material.clone()` —— Three.js 的 clone 共享 material，不隔离的话主件贴完变色会连背景件一起变。

- IO 从 9 点降到 5 点（少了阻挡伸出/退回、顶升到位，多了到位光电 1 点）。

- 文件：`docs/设备三维示意图-产线版.html`（复用 three-global.js，12 步动画）。
- 构型：传送带沿 X（皮带纹理滚动）→ X=200 工位；阻挡气缸（伸出/退回）+ 四角顶升销；
  **贴胶头 X/Y/Z/R 四自由度**（待机 Y=330 → 工件 Y=200），末端压轮 + 胶带卷 + 收膜轮 + 剥离刀；
  相机固定工位上方（Eye-to-Hand），头待机时让开视野、视野锥仅在拍照步显示避免穿模。
- 流程 12 步：WaitCarrier → StopperUp → LiftPin → CaptureAndCorrect → MoveToTapeStart → PressDown →
  TapePath（头 X 180→220 滚贴，胶带 0→40mm 渐长）→ HoldPressure → HeadUp → Release → ConveyOut → RecordOutput。
- 与台式机（现有代码）的关键差异：**贴附期间工件完全静止、头走路径**；传送带并行备料；平台/传送带不再跑四个工位。
- 若要落地到代码要改：IMotionCard 语义重排（X/Y 归头）、流程 15→12 步（删真空/吹气，加阻挡/顶升/放行）、
  IO 表增 4 点（载具到位/顶升到位/阻挡/顶升气缸）、纠偏符号重推、报警表加"载具未到位/堵料"。

- **答案：不能。滚贴只换末端执行器，平台往复一点不减；要减平台运动必须改"谁走路径"（轴分配）。两者正交。**
- 平台现在承担两部分运动：① 工位间转运 0→150→220→350（约 370mm）+ 回程约 350mm；② 贴附路径 200→240（40mm）。
  按 100mm/s 算单件约 7s，是节拍瓶颈（工件在动、相机与头分居 X=150/220 两处）。
- 平台往复的**真正根源**是"相机与贴胶头分居两个固定位置"，不是贴附动作本身。
- 去掉它的三条路：① 把相机与头合并到同一工位（相机装在贴附工位上方）；② 头动（龙门），工件不动；
  ③ Eye-in-Hand 把相机装在贴胶头上，连"拍照位"都省掉（但要做手眼标定）。
- 即使改成头动，平台仍要保留"上料定位"的一下，不存在绝对不动。

- **结论：不必。滚贴的本质是"压轮与工件的相对运动"，谁动都物理等价。**
- 三种组合：① 平台动 + 头轻（只有 Z/R，末端换压轮+供料卷）＝本项目最小改动，`MoveToTapeStart/TapePath`
  与坐标基准全不用改；② 龙门头动（大台面、工件不宜搬）；③ 传送带 + 头动（工件被阻挡销锁死，才"必须"头动）。
- 若真改头动要付的代价：轴分配重排（头 X/Y/Z/R）、视觉纠偏的坐标基准从平台换成头且符号要重推、
  头载胶带卷/收膜轮惯量大 → X/Y 动态精度下降、线缆走线要过拖链。
- R 轴语义会变：直线路径只需保持 Δθ 纠偏；曲线路径要 R 跟随路径切线（变成姿态轴）。
- 现场常被忽略的点：压轮方向必须对齐路径切线，否则胶带侧向起皱；台式机靠平台走直线最省事。

- **结论：既不是整条固定在头上，也不是整条固定在工件上，而是"正在转移"**：已贴段随工件走、未贴段连着供料机构，
  分界点在**压轮**（滚贴头），压轮只负责施压，不"持有"胶带。
- 三种机制：① pick&place 点贴（吸嘴吸整段→Z 下降→断真空/吹气抬起，**没有路径**）；
  ② 滚贴（胶带卷→导向轮→剥离刀剥离型膜→压轮转向→压到工件→收膜轮，路径中连续放出）；
  ③ 本项目现状（真空吸整段 + 平台走路径 + 最后吹气）= **物理不自洽**。
- 不自洽的原因：真空吸力远大于初粘力，胶带不会自己从吸嘴转到工件；工件相对胶带滑动只会把胶带刮皱/拽走。
  项目里"走路径"能成立的前提是加压轮（滚贴）或改成点贴（取消路径）。
- 代码证据：`VacuumOnStep`（步骤 8）在路径前、`VacuumOffAndBlowStep`（步骤 12）在保压后，
  整个 9/10 步期间真空保持 → 模型等价于"胶带全长固定在吸嘴上"。
- 两条修法：A 点贴（删步骤 9/10，Z 下降后直接断真空抬起，适合小片双面胶）；
  B 滚贴（加供料卷+剥离刀+压轮+收膜轮，真空降级为"接料/引带"，X04 余量检测接进供料）。

- **穿模再修（3D 版）**：上一版 `Z0` 只算了工件厚 6，漏了平台板厚 10 → 工件顶面实际在世界 y=16。
  改为 `Z0 = PLATE_TOP(10) + WORK_T(6) = 16`；相机视野锥底面同时从 y=14 抬到 22。2D 版无此问题（工件从台面 z=0 起）。
- 用户观点：① 贴胶时平台往复不合理；② 产线应是传送带，工件一个隔一个随线走；③ 头往复比平台往复合理；
  ④ 既然原流程没有"取胶带"，不如用"挤牙膏"式边挤边涂，省掉取胶。
- 我的结论：
  1. 本项目是**单工位台式机**（工件随平台走、相机/贴胶头固定 X/Y），inline 产线是**传送带 + 龙门头**，两者都真实存在，属产品形态差异不是错误。
  2. 胶带贴附的工业自动化解**不是挤胶**，而是 **胶带供料头（tape feeder）**：胶带卷 → 张紧轮 → 剥离刀(peel plate) → 吸嘴/压轮，
     自动供料，正好补上"取胶带"这个空白，且不改变"贴固态胶带"的工艺本质。
  3. "挤牙膏" = **点胶/涂胶（dispensing）**，是流体计量工艺，另一套设备：时间-压力阀 / 螺杆阀(auger) / 活塞阀 / 喷射阀(jet)；
     参数变成胶压、阀开时间/螺杆转速、走线速度、胶宽、固化方式；报警变成堵胶、气泡、胶量不足、固化；仍需双 MARK 纠偏。
  4. 若真改 inline 点胶：轴 = X/Y 龙门 + Z + R；传送带独立电机 + 阻挡气缸 + 顶升销/视觉二次定位（皮带定位只有 ±0.5~1mm）；
     节拍由贴胶头最长动作决定，传送带可并行备料。
- 未落地：是否出 v3（在线式点胶概念图）待用户确认；现有两版图必须保持与代码一致（平台动），不能偷偷改成头动。

## 产出：Three.js 版三维示意图（用户说"可以"后实现）

## 技术选型答疑：用 Three.js 是否要先建模（用户问）
- 结论：Three.js 是**渲染器不是建模器**，你要么在代码里造几何体，要么导入别人造的模型，"不建模"不存在。
- 路线 A（代码造）：`BoxGeometry/CylinderGeometry` + 材质 + position/rotation，本设备 4 轴 + 几个盒子足够，
  等价于把现有 2.5D 投影换成真透视相机，工作量≈1~2 天。
- 路线 B（CAD 导入）：SolidWorks/UG → glTF/GLB → `GLTFLoader`。坑：① Three.js **Y-up** 而 CAD 多为 Z-up（`rotateX(-π/2)`）；
  ② 单位多为 mm，需 `scale 0.001` 或全场景统一；③ **每个可动件必须单独命名**（Platform / HeadZ / Nozzle）否则整体动不了；
  ④ 装配层级要保留成 Group；⑤ 面数常几十万，需减面 + Draco/meshopt 压缩，否则浏览器卡。
- 当前环境外网受限 → `three.module.js` 必须下载放本地，不能靠 CDN；现有单文件零依赖方案正是为规避这一点。
