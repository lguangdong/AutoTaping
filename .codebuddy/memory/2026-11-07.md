## AutoTaping S2（硬件抽象 + Virtual 实现）实施完成

范围：严格按 `docs/11-开发任务分解.md` 的 S2 交付物，未提前做 S3+（真实 Leadshine/Hikvision 留到 S8）。

### 新增代码结构
- `Core/Abstractions/`：`IMotionCard`（含 `AxisId` 枚举 + `AxisFaultEventArgs`）、`ICamera`（含 `CaptureResult` + `CameraFaultEventArgs`）、`IIoService`，签名逐字对齐 02/03 文档。
- `Core/Exceptions/HardwareException`：带 DeviceName + ErrorCode，定义在 Core（Hardware 引用 Core，不能反向）。
- `Hardware/Motion/`：`MotionErrorCodes`（停止原因 0~4 常量 + 报警码 AL100~AL103 映射 + 中文描述）、`VirtualMotionCard`。
- `Hardware/Camera/`：`VirtualCamera`（合成图 + 偏移注入 + 掉线/重连模拟）。
- `Hardware/Io/`：`VirtualIoService`（内存点位 + SetDi 手动置位 + ForceOutput）。
- `App/App.xaml.cs`：新增 `RegisterHardware` + `ReadAxisSoftLimits` + `ReadIoPointKeys`，按 UseVirtual 选择实现。
- `Tests/`：`VirtualMotionCardTests`（3 用例）+ `VirtualCameraTests`（2 用例），Tests.csproj 加 Hardware 引用。

### 关键决策（后续阶段沿用）
1. HardwareException 放 Core/Exceptions（Hardware 层抛、Core 流程引擎要 catch，故必须定义在 Core 而非 Hardware）。
2. VirtualMotionCard 位置按真实时间戳推进（`Environment.TickCount64` + 耗时 = 距离/速度），比"每 tick 累加 step"更精确，`MoveAbsolute(X,100,100)` 约 1s 精确到位。
3. 软限位拒绝 = 触发 AxisFault(reason=3) + 抛 HardwareException；急停拒绝 = 抛 HardwareException(reason=2)，复位(ResetAxis)后恢复。
4. 急停是每轴锁（`_estop[4]`），`EmergencyStopAll` 置全部，`ResetAxis` 逐轴解除（对齐 S6 状态机 EStopped→NotReady 需 4 轴 ResetAxis）。
5. VirtualCamera 合成图用纯 C# 生成 byte[]（底色 40 + 十字 MARK 255 + 噪声），不引入 OpenCvSharp 到 Hardware（OpenCvSharp 留 S5 进 Vision 项目）。
6. 偏移模型：默认随机 ±5px，`InjectOffset(dx,dy)` 注入固定偏移（S5 演示用），`LastOffsetX/Y` 暴露供验证。
7. `appsettings.json` 的 `UseVirtual` 改为 `true`（S2~S7 无硬件开发，S8 接真实硬件时改回 false）。
8. Virtual 软限位/IO 点位从 appsettings 读取（`Hardware:MotionCard:Axes` 的 Min/MaxLimit、`Io:DiMap/DoMap` 键），缺省兜底 00 文档示例值。

### 验证结果
- `dotnet build AutoTaping.sln` → 0 warning / 0 error。
- `dotnet test` → 17/17 通过（S1 的 12 个 + S2 新增 5 个）。

### 待确认（需用户决定）
1. S2 验收第 1 条「UseVirtual=true 时 Initialize 返回 true」目前通过单测直接 new 验证；DI 集成解析未做（Tests 不引用 App 的 WPF 项目），如需 DI 级集成测试再补。

### 关键决策（后续阶段沿用）
1. 页面切页用「VM + DataTemplate」：`ContentControl.Content = CurrentPage`，MainWindow.Resources 里 8 个 DataTemplate 映射
   VM→Page；页面 UserControl 无参构造、DataContext 由 ContentPresenter 给，DI 只注册 VM（8 个 `PageViewModel` 单例）。
2. 权限不足的导航**保持 IsEnabled=true**，靠 `DataTrigger IsAllowed=False` 置灰，点击由 ShellViewModel 再校验并提示
   "进入「X」需要技术员权限"——同时满足 07 的"置灰可见"和 08 的"点击时提示"。
3. 自动锁屏：`IdleMonitor`（App/Infrastructure，InputManager.PreProcessInput + DispatcherTimer 1s）只发事件；
   ShellViewModel 判 `Running/Paused` 不锁 → Logout → 抛 `LockRequested`；由 **App**（窗口生命周期归它）隐藏主窗口并弹登录框，
   取消则 Shutdown。App.xaml 改 `ShutdownMode=OnExplicitShutdown`（登录框与主窗口交替出现，不能因最后一个窗口关闭而退出）。
4. 状态栏每秒刷新：`PeriodicTimer` + `Task.Run` 后台读库（配方/产量/良率/未确认报警），再经 `IUiDispatcher` 切回 UI 线程赋值；
   读库失败只跳过本次并记日志，循环不死。时钟文本也由同一循环产出（1s 一跳）。
5. **踩坑记录（会再犯）**：`RowDefinition.Height` / `ColumnDefinition.Width` 需要 `GridLength`，资源里写成 `sys:Double`
   会在运行时抛"64 不是属性 Height 的有效值"；`Button.Width` 反而要 Double。故 Styles.xaml 里同时保留
   `NavColumnWidth`(GridLength) 与 `NavButtonWidth`(Double)。

### 关键决策
1. 采集线程放 Core（`DeviceMonitor`），不是 App：S6 的互锁与流程引擎也要读快照；页面只读 `IDeviceMonitor.Current`，
   自己起 200ms `PeriodicTimer` 把快照搬到 UI 线程（进入页启动、离开页 Cancel+Dispose）。
2. 页面生命周期加到 `PageViewModel`：`OnEnteringAsync`（返回 false 拒绝进入，手动页确认框用）/ `OnLeaveAsync`
   （停点动 + ClearAllForcedOutput + Z 抬到 Process:SafeHeight，非阻塞下发）/ `RequestNavigation(PageKey)` 事件由 Shell 执行。
   NavigationItem 命令改为 AsyncRelayCommand（默认不允许并发执行）。
3. 急停判定（S4 无状态机）：任一轴 StopReason==2 或 DI X06=0 → 手动页所有控制禁用 + 红色提示 + 日志；
   点表没有 X06 时不判定，避免配置缺失把整页禁死。
4. 点动按钮用附加行为按住/松开，不写 code-behind；`StopJogCommand` 不设 CanExecute，急停时也能停。
5. 目标位置：非数字/超软限位 → 红框 + 错误文案（带范围）+ 定位按钮禁用；未回零同样禁用定位；
   下发前再校验一次软限位（防御性）。
6. appsettings 新增两组键（文档未定义，已在汇报中标注）：`Manual:{JogSpeedMmPerSec,MinSpeedMmPerSec,MaxSpeedMmPerSec}`、
   `Io:InitialDiStates:{X05,X06,X07}=true`（虚拟模式安全回路初值，否则 X06=0 会被判急停）。
   `Io:DiMap/DoMap` 的**值改成中文名**（08 页面 7 要求中文名来自这两个映射；01 §7 示例是英文，二者冲突，取 08）。
7. 手动页 IO 网格只读；IO 强制输出只做在 IoPage（08 页面 2 布局里的"进入强制模式"未实现，见待确认）。
